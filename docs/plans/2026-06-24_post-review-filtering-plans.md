## Plan 1 — Apply Contamination Decisions to `data/real/`

### Context
The manual review in script 14b is complete. 851 images were confirmed as containing genuinely different animal species and should be removed from the dataset. 6,739 images were rejected (false positives: secondary boxes are actually the same class). Script 15 (`scripts/dataset_quality/15-apply_contamination_decisions.py`) already exists and applies the decisions JSON directly to the three COCO split files in `data/real/`.

**Decision translation already done by script 14b:**
- `confirm` → `"discard"` (all significant boxes contaminated) or `"edit"` (drop specific box indices)
- `reject` → `"keep"` (image unchanged; all conf ≥ 0.5 boxes remain as GT)

### Files involved
- **Input decisions:** `reports/multi_animal_contamination_decisions.json` (regenerated by 14b on each commit — already current)
- **Targets:** `data/real/annotations_train.json`, `data/real/annotations_val.json`, `data/real/annotations_test.json`
- **Script:** `scripts/dataset_quality/15-apply_contamination_decisions.py`

### Steps

**Step 1 — Verify decisions are complete:**
```bash
python3 -c "
import json
data = json.load(open('reports/multi_animal_contamination_decisions.json'))
from collections import Counter
c = Counter(v['decision'] for v in data.values())
print(f'Total entries: {len(data)}')
print('By decision:', dict(c))
"
```
Expected: ~7,590 entries (851 confirm → discard/edit + 6,739 reject → keep).

**Step 2 — Dry-run to check class-level impact:**
```bash
python3 scripts/dataset_quality/15-apply_contamination_decisions.py \
    --decisions reports/multi_animal_contamination_decisions.json
```
Without `--force` the script aborts if any class would drop below its tier boundary — review the output.

**Step 3 — Apply with force:**
```bash
python3 scripts/dataset_quality/15-apply_contamination_decisions.py \
    --decisions reports/multi_animal_contamination_decisions.json \
    --force
```

### Note on GT box threshold
The current COCO uses conf ≥ 0.5 as the GT threshold (set by script 12). The review UI showed gray boxes (conf 10–50%) for context but those are NOT currently in the COCO. If the intent is to also include conf 10–50% boxes as GT annotations, a separate post-processing step would be needed after script 15 to supplement annotations by re-reading `speciesnet_results.jsonl`. Confirm the desired threshold before implementing.

### Verification
- Compare image counts in the three COCO JSONs before vs. after
- Confirm that none of the 851 confirmed-contamination images appear in the updated COCOs
- Run a per-class count check to confirm no class dropped unexpectedly

### Implementation (2026-06-24)
- **Backup:** the three COCO JSONs were copied to `data/real/backup_pre_contamination_20260624_103046/` before any mutation (these files are gitignored — no other recovery path).
- **Apply (script 15):** ran with `--force`. Removed contamination annotations only (train −785, val −100, test −459 = **1,344** boxes); **image counts unchanged** (0 discards). No band-safety violations.
- **GT-threshold decision → new script `scripts/dataset_quality/15b-supplement_low_conf_boxes.py`.** Per the user's choice to include conf 10–50% boxes as GT, this script supplements the COCOs with detections in `[0.1, 0.5)` (`source="megadetector_lowconf"`). Reuses script 15's `_iou`, `_bbox_norm_to_xyxy`, `_coco_bbox_to_xyxy`, atomic-write and dry-run-then-write structure. Guards: IoU>0.5 dedup against existing annotations, contamination guard (won't re-add a reviewer-dropped box on `edit` images), default `--species-filter off`. **16,911** boxes added (train 9,676 / val 1,398 / test 5,837).
- **Orchestrator correction:** category resolution was changed to prefer each image's existing-annotation `category_id` (verified reliable — 0 images carry mixed categories), with folder-name parsing only as a fallback. The original folder-name approach silently skipped `baird's tapir` (folder `bairds_tapir` lacks the apostrophe) and a few cross-source folder-naming variants. After the fix, all non-blank images resolve; only intentional `data/blanks/` negatives are skipped.
- **Verified:** every `megadetector_lowconf` annotation has `conf ∈ [0.1, 0.5)`; **0** low-conf boxes overlap an original ≥0.5 box (IoU>0.5); **0** overlap a dropped contamination box across 280 checked `edit` images; no duplicate annotation IDs; **idempotent** (a second run adds 0 boxes).

## Plan 2 — Post-Filtering Image Count Overview (Markdown Table)

### Context
After Plan 1 removes contamination-flagged images, the per-class image counts change. We need a fresh count table showing: real split counts, synthetic split counts, total, the current band assignment, whether the band still matches the new counts, and whether any class crossed a band boundary.

### Band thresholds
| Band | Real pool size |
|------|----------------|
| A    | pool < 150     |
| B    | 150 ≤ pool < 250 |
| C    | 250 ≤ pool < 400 |
| D    | pool ≥ 400     |

"Pool" = train + val + test real images for this class (post-filtering).

### Data sources
| What | Source |
|------|--------|
| Real counts (post-filtering) | `data/real/annotations_{train,val,test}.json` — count images per category |
| Synthetic train counts | Band A: 200/class, Band B: 100/class, others: 0 |
| Synthetic test counts | 50/class for all 225 classes |
| Current band assignments | `reports/class_split_counts.csv` (column: `band`) — baseline for comparison |

### New script: `scripts/dataset_quality/17-post_filter_counts.py`

**Logic:**
1. Load all 3 real COCO JSONs; count images per `category_name` per split
2. Derive synthetic train from original band (A→200, B→100, else 0); synth test = 50 for all
3. Load `reports/class_split_counts.csv` for the original band assignment
4. Compute new pool = real_train + real_val + real_test
5. Compute new band from thresholds; flag if it differs from original
6. Write `reports/post_filter_counts.md` — a Markdown table sorted by total (real + synth) descending

### Output table columns
```
| Class | Real Train | Real Val | Real Test | Synth Train | Synth Test | Real Total | Grand Total | Band (orig) | Band (new) | Changed? |
```

Flag rows where `Band (orig) != Band (new)` with a `⚠` marker.

### Verification
- Sum of real_train + real_val + real_test across all classes should equal total images in the 3 updated COCOs
- Band A classes should mostly be unchanged (they were already sparse; contamination flags are rare there)
- At least one Band D class with heavy contamination should show reduced count

### Implementation (2026-06-24)
- **Script:** `scripts/dataset_quality/17-post_filter_counts.py` → writes `reports/post_filter_counts.md`.
- Columns match the plan plus an added **`Real Ann Total`** column, since (with 0 discards) image counts are unchanged and the real filtering impact lives in the annotation counts. The report opens with a caveat note explaining this.
- **Verification passed:** per-class image-count sums match the COCO totals on all splits (train 145,642 + 122 blanks = 145,764; val 12,519 + 26 = 12,545; test 63,796 + 26 = 63,822). Total annotated images: **221,957**.
- **Missing class:** `human` is the one category present in the COCOs (225) but absent from `class_split_counts.csv` (224) — handled as original band `?`.
- **On the "Changed?" column:** 47 classes show `Band(orig) ≠ Band(new)`, but **none of these are caused by filtering** (no images were removed). They are a definitional baseline mismatch — `Band(orig)` was assigned on `effective_pool` (SpeciesNet-filtered subset) while `Band(new)` uses the raw COCO image pool, which is systematically larger (all 47 shifts are upward; e.g. asian elephant B@224 → D@1498). This is documented in the report header.

## Plan 3 — Lookalike Group Suggestions from Rejected Multi-Animal Images

### Context
The 6,739 rejected images are confirmed to contain multiple animals of the **same class** — the secondary boxes were SpeciesNet false positives, not real contamination. This reveals what SpeciesNet confuses with each class. For classes where this happens frequently (> 3 rejected multi-animal images), the misclassified secondary predictions are candidates for the lookalike groups, which suppress spurious contamination flags during future re-runs of script 14.

**Lookalike groups are used in two places:**
- `scripts/dataset_quality/14-flag_multi_animal_contamination.py` — `LOOKALIKE_GROUPS: list[set[str]]` (currently empty)
- `scripts/dataset_quality/16-build_lookalike_groups.py` — `CURATED_OVERRIDES` dict

### Data available per rejected image (from `multi_animal_contamination_review.json`)
- `expected_class` — the true class
- `offending_boxes[*].pred_common` — what SpeciesNet predicted for the secondary box
- `offending_boxes[*].pred_scientific` — scientific name
- `offending_boxes[*].pred_top1_score` — SpeciesNet confidence
- `offending_boxes[*].match_level` — taxonomic distance (species/genus/family/order/class/no_match)

### New script: `scripts/dataset_quality/17b-build_lookalike_candidates.py`

**Logic:**
1. Load `reports/contamination_review_decisions.jsonl`; replay to build `{filepath: latest_decision}` dict
2. Load `reports/multi_animal_contamination_review.json`; filter to filepaths where decision = `"reject"`
3. For each rejected image, iterate `offending_boxes` where `verdict == "flag"`:
   - Extract `(expected_class, pred_common, pred_scientific, match_level)`
4. Count `(expected_class, pred_common)` pairs; record pred_scientific for each pair
5. Filter to classes with > 3 rejected multi-animal images
6. Sort per class by pair count descending
7. Write `reports/lookalike_candidates.csv` and `reports/lookalike_candidates.md`

### Output format (`lookalike_candidates.csv`)
```csv
expected_class,predicted_common,predicted_scientific,count,match_level,review_decision
domestic_horse,domestic cattle,bos taurus,40,class,
llama_genus,white-tailed deer,odocoileus virginianus,31,class,
```
The `review_decision` column is left blank for manual completion: `lookalike` | `different` | `skip`.

### Output format (`reports/lookalike_candidates.md`)
```markdown
## domestic_horse  (45 rejected multi-animal images)
| Predicted as | Scientific | Count | Match level |
|---|---|---|---|
| domestic cattle | bos taurus | 40 | class |
| domestic sheep | ovis aries | 3 | class |

## llama_genus  (38 rejected multi-animal images)
...
```

### Next step after manual review
Once the `review_decision` column is filled in:
1. Update `LOOKALIKE_GROUPS` in `scripts/dataset_quality/14-flag_multi_animal_contamination.py` — add `{class1, class2}` sets for true visual lookalikes
2. Update `CURATED_OVERRIDES` in `scripts/dataset_quality/16-build_lookalike_groups.py` — add cross-genus clusters where applicable

### Verification
- Verify top entries make biological sense: domestic_horse→cattle is a co-occurrence artifact, not a lookalike → mark `different`
- True lookalike candidates are same-family or same-genus predictions (e.g., lynx→bobcat)
- After updating the lookalike groups, re-run script 14 and confirm flagged image count decreases

### Implementation (2026-06-24)
- **Script:** `scripts/dataset_quality/17b-build_lookalike_candidates.py` → writes `reports/lookalike_candidates.csv` and `reports/lookalike_candidates.md`. CLI adds `--min-images` (default 3, strictly greater-than), `--decisions-jsonl`, `--review-json`, output overrides, and `--dry-run`.
- **Run results (verified):** the JSONL replay (handling `undo`) yields 7,271 unique filepaths; **6,477** rejected images were processed; exactly **140** classes meet the `>3 rejected images` threshold, producing **1,733** candidate pairs. The CSV contains precisely those 140 classes — no class below threshold leaked in, none missing. The `review_decision` column is left blank for manual completion.
- **Spot-check (biology):** top global pairs split cleanly into co-occurrence artifacts (`domestic_horse→domestic cattle` 252, `domestic_donkey→domestic cattle` 154, `rhinoceros_family→domestic cattle` 120 — all `class`/`no_match`, mark `different`) vs. plausible same-habitat lookalikes (`bighorn_sheep→mule deer` 95, `bighorn_sheep→red deer` 90, `llama_genus→pronghorn` 120 — `order` level).
- **Next step (unchanged):** once `review_decision` is filled, fold true lookalikes into `LOOKALIKE_GROUPS` (script 14) and `CURATED_OVERRIDES` (script 16), then re-run script 14.
