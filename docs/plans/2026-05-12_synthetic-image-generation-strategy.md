# Synthetic Image Generation Strategy

**Date:** 2026-05-12  
**Status:** In progress — 760 images generated (~10/class × 76), 11,840 pending

---

## 1. Overview and Scope

The dataset construction strategy (see `docs/plans/2026-05-04_dataset-construction-strategy.md`) requires synthetic images for two bands:

| Band | Classes | Images/class | Total | Budget |
|------|---------|--------------|-------|--------|
| A | 50 | 200 | 10,000 | €500 |
| B | 26 | 100 | 2,600 | €130 |
| **Total** | **76** | — | **12,600** | **€630** |

All images will be generated by the Gemini image generation model (accepts up to 32,000 tokens of prompt input), using highly detailed per-species prompts drawn from the Wikipedia articles in `data/wikipedia/`. The output is a JSONL file (`data/synthetic/image_list.jsonl`) consumed by a generation script. This document defines what goes into that list and why.

---

## 2. Why Animal-Specific Prompts Are Necessary

A generic "animal in its habitat" approach fails for this use case because:

- **Behavior is species-specific**: A walrus cannot climb a tree; a kinkajou does not stand on an ice floe. Mismatched scenes are worse than useless — they teach the wrong visual associations.
- **Diagnostic features must be visible**: Detection and classification depends on species-specific markers (tusks, stripes, horn shape, tail morphology, fur texture). The prompt must explicitly demand these features are correctly rendered.
- **Habitat distributions differ widely**: Training on "forest" images for a desert species reduces out-of-distribution robustness rather than improving it.

The 76 classes span ecological guilds from aquatic pinnipeds to nocturnal arboreal primates. Prompts must be tailored per guild and per species.

## 3. Six Dimensions of Image Variation

Each image in the list is defined by six independently varying axes. Not all combinations are valid for every species — the per-species schedule (Section 6) applies appropriate constraints.

### 3.1 Camera Angle / Perspective

| Code | Description | Notes |
|------|-------------|-------|
| `eye_level` | Camera at same height as animal's mid-body | Most natural; primary for val set |
| `low` | Camera below animal, looking slightly upward | Emphasizes size, underside features |
| `high` | Camera above animal from an elevated natural vantage point (hillside, rock outcrop, vehicle roof) — oblique downward angle, not directly overhead; full body remains visible | Good for body pattern visibility |
| `side_profile` | Pure lateral view, full body | Silhouette; maximises body shape signal |
| `three_quarter_front` | ~45° front-diagonal | Standard field guide angle |
| `three_quarter_rear` | ~45° rear-diagonal | Less common; challenges model |
| `head_on` | Full frontal, direct face view | Key for facial recognition; distinctive ears, horns |
| `rear` | Animal facing away from camera or walking away | Whole animal visible with rear aspect toward camera; full body in frame |
| `closeup_head` | Tight crop of head and face | Highest species ID signal; mandatory in train set |

### 3.2 Subject Distance

| Code | Frame occupancy | Typical scene |
|------|----------------|---------------|
| `close` | Animal fills ~50–70% of frame | Binocular / telephoto portrait; simulated ~20–80 m depending on species size |
| `medium` | Animal fills ~20–40% of frame | Standard binocular field view; simulated ~80–250 m |
| `far` | Animal fills <10% of frame | Animal at or near limit of binocular range; >250 m; habitat context dominant |

> Frame occupancy is as rendered through the 400–600 mm telephoto lens specified in the photography style. The `close` band does not represent an animal standing a few metres away — it represents what a large animal looks like when a binocular user fills the eyepiece with it at ~50 m.

### 3.3 Pose / Behavior

Universal behaviors (all species can exhibit these with appropriate context):
- `standing_alert` — upright, head raised, attentive
- `walking` — natural locomotion, mid-stride
- `running` — full gallop or sprint
- `resting` — lying down or sitting
- `eating_foraging` — feeding on species-appropriate food
- `drinking` — at water source
- `grooming` — self-grooming, scratching
- `looking_at_camera` — direct eye contact
- `vocalizing` — mouth open, calling

Species-specific behaviors are defined in the per-class schedule (Section 7) and drawn from Wikipedia behavior sections.

**Single-animal constraint.** Every image shows exactly one animal. Where age or sex classes differ visually, distribute images across *adult male*, *adult female* (for strongly dimorphic species), and *juvenile* subjects — not as separate shot categories but as a per-image attribute rotated throughout the schedule. For species where juveniles have distinct coloration or proportions (e.g. walrus young are dark brown; red brocket calves are spotted), ~15–20% of images should use a juvenile subject. For strongly dimorphic species (e.g. saiga — only males have horns; mouflon — horns differ greatly) split images ~50/50 between male and female.

### 3.4 Environment / Habitat

The primary and secondary habitats are species-specific (see Section 6). Universal options:

| Code | Description |
|------|-------------|
| `primary_open` | Main habitat, unobstructed, good light |
| `primary_vegetation` | Main habitat, partly obscured by plants |
| `forest_interior` | Dense canopy, dappled light |
| `riparian` | Riverbank, stream edge, muddy margins |
| `in_water` | Swimming, wading (semi-aquatic only) |
| `rocky` | Boulder field, cliff, scree |
| `canopy` | High in trees, on branches (arboreal only) |
| `snow` | Snow-covered ground or ice (cold-climate only) |
| `arid` | Dry scrub, sand, sparse vegetation |
| `burrow` | Den entrance, excavation site (fossorial only) |

### 3.5 Lighting

| Code | Description |
|------|-------------|
| `golden_hour` | Warm directional light, long shadows |
| `overcast` | Soft diffuse, no hard shadows |
| `midday` | Harsh overhead sunlight |
| `dappled` | Intermittent light through canopy |
| `backlit` | Sun behind animal, rim lighting, partial silhouette |

### 3.6 Occlusion / Visibility

| Code | Description |
|------|-------------|
| `none` | Fully visible, no obstruction |
| `partial_vegetation` | 20–40% of body occluded by grasses, branches, leaves |
| `heavy_vegetation` | >40% occluded; only part of body visible |
| `emerging` | Animal moving out from dense cover, front half visible |
| `semi_submerged` | Lower body in water (aquatic/drinking scenes) |

**Visibility requirement.** The animal must be clearly identifiable in every image. `partial_vegetation` may be used in approximately 10% of images (≈20 of 200 for Band A, ≈10 of 100 for Band B). `heavy_vegetation` should not appear in the scheduled shot list; it may only occur as a natural side-effect of an arboreal canopy environment setting. For aquatic or semi-aquatic species that are commonly encountered in water (walrus, pinnipeds, Malay tapir, water deer, otters, mink), `semi_submerged` must appear explicitly in the prompts of a dedicated image subset — this is not optional for these species, as it is a primary viewing context.

## 4. Shot Type Schedules per Class

### 4.1 Band A — 200 images per class (160 train + 40 val)

The 40 val images are pre-designated (not random) and use "prototypical" shot parameters. The 160 train images systematically cover challenging dimensions.

**Val set (40 images) — prototypical wildlife photograph:**

| Count | Angle | Distance | Behavior | Notes |
|-------|-------|----------|----------|-------|
| 8 | `eye_level` | `medium` | `standing_alert` | Various environments (primary habitat) |
| 8 | `eye_level` | `medium` | `walking` | Various environments |
| 8 | `three_quarter_front` | `medium` | `eating_foraging` | Natural feeding context |
| 8 | `eye_level` | `medium` | `resting` | Relaxed pose |
| 8 | `three_quarter_front` | `medium` | `looking_at_camera` | Direct engagement |

All 40 val shots: overcast or golden-hour lighting, no or minimal occlusion, primary habitat. These resemble what real camera-trap or nature-photography test images look like.

**Train set (160 images) — systematic challenge coverage:**

| Count | Angle | Distance | Behavior / Special |
|-------|-------|----------|--------------------|
| 25 | `eye_level` | `medium` | Full-body, eye-level; replaces former `closeup_head/close` (see note below) |
| 20 | `low` | `medium`–`close` | Looking down at camera; habitat floor context |
| 15 | `high` | `medium` | Elevated vantage; body pattern visible |
| 15 | `head_on` | `medium`–`close` | Direct frontal; ears, horns, facial structure |
| 15 | `rear` | `medium` | Whole animal walking away; full body from rear |
| 15 | `side_profile` | `medium`–`far` | Full silhouette |
| 10 | `three_quarter_rear` | `medium` | Less-common angle |
| 10 | `three_quarter_front` | `medium` | Standard field-guide angle |
| 10 | `eye_level` | `far` | Small in landscape; habitat context |
| 15 | `eye_level` | `close`–`medium` | Prominent in frame; binocular portrait |
| 10 | varies | `medium` | Partial vegetation only (animal clearly visible throughout) |

Within each group, rotate through available behaviors, environments, and lighting to maximize diversity. Species-specific behaviors (e.g., climbing for kinkajou, swimming for otter) should appear across multiple groups rather than only in one.

> **Note — `closeup_head` removed (2026-05-13).** The original schedule used `closeup_head/close` (animal fills 50–70% of frame, head/face tightly cropped). Preview images showed the animal was frequently cut off at frame edges, which limits data augmentation: a fully-visible animal can be scaled down and padded to train detection at smaller apparent sizes, but a cropped animal cannot be shrunk without worsening the crop. The 25 closeup_head shots were replaced with 25 `eye_level/medium` shots. The `focus_note` (species diagnostic feature guidance) was retained unchanged — it remains useful guidance at any distance. The change was applied via `1c-migrate_closeup.py` to all 1,488 pending prompts; the ~12 already-generated closeup_head images per class were left as-is.

### 4.2 Band B — 100 images per class (all training)

All 100 synthetic images go to training. The validation set for Band B comes from the surplus real images (those not sampled into the 100-image real training set).

Band B synthetic images should complement the real training images, not duplicate them. However, since the real training sample is drawn before prompts are generated, the complement-focus is applied in a second pass once the real training sample is known. For the initial image list, use a training-only distribution similar to the Band A train set (scaled down):

| Count | Angle | Distance | Notes |
|-------|-------|----------|-------|
| 15 | `eye_level` | `medium` | Full-body; replaces former `closeup_head/close` (see Band A note) |
| 12 | `low` | `medium` | Upward perspective |
| 12 | `high` | `medium` | Overhead perspective |
| 12 | `head_on` | `medium` | Frontal |
| 12 | `rear` | `medium` | Whole animal from rear |
| 10 | `side_profile` | `medium`–`far` | Full body profile |
| 8 | `three_quarter_front` | `medium` | Field-guide angle |
| 8 | `eye_level` | `far` | Landscape context |
| 5 | varies | `medium` | Partial vegetation (animal clearly visible) |
| 6 | varies | varies | Species-specific behavior/habitat gaps |

## 5. Train / Validation Split Design

### 5.1 The core constraint

The benchmark test set for all bands uses **real images only**. Synthetic images are never used for final evaluation. The split question is purely about the **training-loop validation set** — used for early stopping, learning rate scheduling, and overfitting monitoring during the training run, not for the reported results.

### 5.2 Band A

Real images in Band A are too few (6–149 per class) to withhold any for training-loop validation. All real images go to the test set. Therefore, the training-loop val set must come from synthetic images.

**Decision: 160 train / 40 val synthetic split, curated by shot type.**

The 40 val images use "prototypical" parameters (eye-level, medium distance, fully visible, natural habitat) so they approximate what real field images look like. The 160 train images use all unusual and challenging combinations.

**Why not random split?** A random 80/20 split of synthetic images would put some close-up head shots and extreme-angle shots into val. These do not resemble typical wildlife photographs and would give a misleading validation loss signal. A random val set optimizes for synthetic image performance; the curated val set optimizes as a proxy for real-image performance.

### 5.3 Band B

Band B has 100 real training images and 50–149 real test images (the surplus after the training sample is drawn). A small real validation set (~15–20 images) can be carved from the test pool before finalizing, keeping both training and test sets clean. This is decided at training time, not at prompt generation time.

All 100 synthetic Band B images go to training — no synthetic val is needed or desired.

### 5.4 The `split` field in image_list.jsonl

The JSONL file pre-assigns every Band A image to `"train"` or `"val"` based on its shot_type. Band B images are all `"train"`. This removes any ambiguity at training time.

## 6. Animal-Specific Customization

### 6.1 Ecological Guilds

Each species is assigned to one or more ecological guilds. The guild determines which environments and behaviors are emphasized in the shot schedule, overriding generic defaults.

| Guild | Key traits | Environment emphasis | Behavior emphasis |
|-------|------------|---------------------|-------------------|
| **Arboreal** | Tree-dwellers; prehensile limbs/tail | `canopy`, `forest_interior` | climbing, hanging, moving through branches |
| **Semi-aquatic** | Spend significant time in water | `in_water`, `riparian` | swimming, wading, grooming on riverbank |
| **Fully aquatic** | Ocean or sea habitat | `in_water`, `rocky` shore, ice | swimming, hauled-out, diving |
| **Fossorial** | Burrow-digging; often nocturnal | `burrow`, `arid`, `primary_open` | digging, emerging from burrow, nocturnal low-light |

### 6.4 Using Wikipedia Articles in Prompts

**Which sections to extract:**

1. **Description / Characteristics** (mandatory) — physical features, size, coloration, distinctive markings, sex differences, coat texture. This is the most critical section: it tells Gemini how the animal should look.

2. **Behaviour / Ecology** (mandatory) — activities, postures, locomotion, feeding, social interactions. Informs which behaviors are plausible in generated scenes.

3. **Habitat / Distribution** (mandatory) — primary and secondary habitats, vegetation type, terrain, climate. Informs environment setting.

4. **Reproduction / Life cycle** (optional) — useful only for mother-with-juvenile shots.

**How much text to insert:** Insert the full raw text of the relevant sections without summarizing. Gemini handles 32k token inputs and more text is never worse than less. The Description section of most Wikipedia articles is 300–1,500 words — include it in full.

**Genus / family classes — iNaturalist top-species mapping**

For every class whose level is `genus` or `family`, `scripts/wikipedia/2-scrape_wikipedia.py` automatically resolves the representative species list via the iNaturalist API:

1. Resolve the taxon's iNaturalist ID by querying `/v1/taxa?q={scientific_name}&rank={genus|family}`.
2. Query `/v1/taxa?taxon_id={id}&rank=species` — iNaturalist returns child species sorted by observation count (most-photographed first).
3. Exclude any species already listed as a standalone entry in `reports/classes_225.csv` (the overlap exclusion rule — e.g. *Leopardus pardalis* must not appear as a sub-species under the *Leopardus* genus entry).
4. Take the top-5 remaining species. Results are saved to the `top_species` list in `reports/wikipedia_urls.json`, each entry carrying `scientific_name`, `common_name`, `inat_observations`, `wikipedia_file`, and `wikipedia_found`.
5. Wikipedia is fetched for each top species and saved to `data/wikipedia/{species_name}.txt`.

**Fallback:** If the iNaturalist API returns no results, the script falls back to `reports/genus_species_mapping.csv` and `reports/family_species_mapping.csv`.

**Using the top species in prompts:** For a genus-level class with N representative species, distribute images across species — approximately `images_per_class / N` per species. Each species gets its own Wikipedia description text in the prompt (genus article + species article). The SUBJECT line should read: "*[common name]* (*[species scientific name]*), a member of the *[genus]* group". This ensures all top-5 species are visually represented in the synthetic dataset for that class.

## 7. Prompt Template

Each image in image_list.jsonl stores a fully-rendered prompt. The template below is used by the generation script, with species-specific content filled in.

```
TASK: Generate a single photorealistic wildlife photograph for use in a computer vision object detection training dataset. The photograph must look like an authentic field photograph taken by a wildlife photographer or camera trap.

SUBJECT: {common_name} ({scientific_name})

SPECIES DESCRIPTION:
{wikipedia_description_section — full raw text, typically 300–1500 words}

NATURAL BEHAVIOR AND HABITAT:
{wikipedia_behavior_section — full raw text, typically 300–1000 words}
{wikipedia_habitat_section — full raw text, typically 200–600 words}

SCENE SPECIFICATION:
- Camera angle / perspective: {angle_description}
- Distance from subject: {distance_description}
- Animal pose / behavior: {behavior_description}
- Environment / background: {environment_description}
- Lighting conditions: {lighting_description}
- Occlusion / visibility: {occlusion_description}
- Special focus: {focus_note}

PHOTOGRAPHY STYLE: Documentary wildlife photography, comparable in quality and style to BBC Natural World or National Geographic. {photography_style} No studio lighting, no artificial backgrounds, no text overlays, no watermarks, no borders, no frames, no human-made objects unless contextually relevant to the scene.

CRITICAL REQUIREMENTS:
1. The {common_name} must be the unmistakable primary subject of the photograph.
2. The following species-diagnostic features must be clearly visible and anatomically correct: {key_diagnostic_features}
3. The animal's body proportions, coloration, and posture must match the species description above exactly.
4. The scene must be ecologically plausible — the environment, weather, and behavior must all occur naturally for this species.
5. The photograph must be suitable for training an automated species identification system.
6. The animal must be fully visible within the frame — no part of its body, head, or limbs should be cut off at the image edges.
```

### 7.1 Photography Style Variants

The `{photography_style}` placeholder takes one of two values depending on the `bokeh` field in `index.jsonl`:

**`bokeh: true`** — telephoto portrait style (used for the first 5 preview images per class):
> Telephoto lens (400–600 mm equivalent), natural shallow depth of field with background softly blurred, authentic field conditions.

**`bokeh: false`** — binocular observation style (used for all remaining 12,220 images):
> Wildlife observation through optical binoculars (8–10× magnification), full-scene sharp focus, authentic field conditions. No background blur — the animal is integrated into its environment, not isolated against a softened background.

**Rationale.** Visual inspection of real AX Visio binocular images (`resources/AX_Visio_images/`) showed that the binocular optics produce fully sharp backgrounds with zero bokeh — the animal is embedded in its environment, not isolated against a blurred background. Training exclusively on bokeh-style images would create a harmful domain gap: the detector would see clear subject/background separation during training that does not exist at inference time. The binocular style is therefore the correct default. The 380 bokeh images are retained as generated to avoid waste and add minor diversity, but they are not the target style.

The two style constants are defined in `scripts/synthetic/1-generate_image_list.py` as `PHOTOGRAPHY_STYLE_BOKEH` and `PHOTOGRAPHY_STYLE_NO_BOKEH`, and `build_prompt()` selects between them via a `bokeh: bool` parameter.

### 7.2 Worked Example: Walrus close-up head shot (train)

```
TASK: Generate a single photorealistic wildlife photograph for use in a computer vision object detection training dataset. The photograph must look like an authentic field photograph taken by a wildlife photographer or camera trap.

SUBJECT: Walrus (Odobenus rosmarus)

SPECIES DESCRIPTION:
The walrus (Odobenus rosmarus) is a large flippered marine mammal with a discontinuous distribution about the North Pole in the Arctic Ocean and subarctic seas of the Northern Hemisphere. The walrus is the only living species in the family Odobenidae and genus Odobenus. This species is subdivided into two subspecies: the Atlantic walrus (O. r. rosmarus) which lives in the Atlantic Ocean and the Pacific walrus (O. r. divergens) which lives in the Pacific Ocean. Adult Pacific walrus weigh between 800 and 1,700 kg (1,800 and 3,700 lb) and Atlantic walrus are somewhat smaller. The walrus is characterised by its prominent tusks, whiskers, and great bulk. Most male Pacific walruses weigh about 800–1,700 kg (1,800–3,700 lb) and females weigh about 400–1,250 kg (880–2,760 lb). Males reach sexual maturity at 7 years but do not begin breeding until 15 years; females first ovulate at 6–7 years old. The walrus has a thick layer of vascularized blubber, up to 15 cm (6 in) thick, under the hide. Both male and female walruses possess prominent tusks, elongated canine teeth which are present in both sexes and can reach 1 m (3 ft 3 in) in length and 5 kg (11 lb) in weight. They are used to form and maintain holes in the ice, and assist walruses in climbing out of the water onto ice. The skin is thick and wrinkled; it is initially light brown but darkens with age, and becomes rougher and more prominent over the body. When walruses stay in the water for extended periods of time their skin appears lighter because blood is directed away from the skin surface to prevent heat loss. The skin of the head and neck is mostly bare. Walruses have large amounts of tough, pale pink or white vibrissae (whisker) on their face, arranged in a horseshoe-shaped pad on the rostrum.

NATURAL BEHAVIOR AND HABITAT:
Walruses are gregarious animals that generally haul out in large herds on rocky beaches or ice floes. Walruses mostly haul out on sea ice to give birth and nurse their young, and use ice as a resting platform between dives. They may haul out on rocky shorelines if no ice is available. The Pacific walrus migrates annually from the Bering Sea to the Chukchi Sea when the ice breaks up in summer, and returns in winter. Walruses are not deep divers compared to other pinnipeds; they typically forage at depths of 30 to 50 m (98 to 164 ft) for no longer than 30 minutes. They are bottom feeders and eat mostly benthic invertebrates. Their main diet consists of clams, worms, snails, soft corals, tunicates, sea cucumbers, various crustaceans, and other marine invertebrates. Young walruses are dark brown and grow paler and more cinnamon-colored as they age.
```

## 8. File Layout

### 8.1 Why not a single JSONL

Embedding full prompt text in a single `image_list.jsonl` produces a file in the range of **200–300 MB** (12,600 images × ~5,000 token average prompt × ~4 chars/token). That file is:

- Too large to diff meaningfully in git
- Slow to load for any single-image operation (re-generation, status update, inspection)
- Impossible to edit one prompt without touching a 12,600-line file

### 8.2 Layout

```
data/synthetic/
├── index.jsonl               ← lightweight master index, no prompt text (~6 MB)
├── prompts/
│   ├── walrus/
│   │   ├── 001.txt           ← one file per image, prompt text only
│   │   ├── 002.txt
│   │   └── ...200.txt
│   ├── kinkajou/
│   │   └── ...100–200.txt
│   └── ...76 class dirs
└── images/
    ├── band_a/
    │   └── {class}/
    └── band_b/
        └── {class}/
```

**index.jsonl** — one record per image, all metadata fields, no prompt text:

```json
{
  "filename":     "a_walrus_001.jpg",
  "class":        "walrus",
  "scientific":   "Odobenus rosmarus",
  "band":         "A",
  "split":        "train",
  "shot_type":    "closeup_head",
  "distance":     "close",
  "lighting":     "overcast",
  "occlusion":    "none",
  "prompt_file":  "prompts/walrus/001.txt",
  "bokeh":        false,
  "status":       "pending"
}
```

**Prompt files** (`prompts/{class_slug}/{nnn}.txt`) — plain UTF-8, prompt text only, no JSON wrapping. Each file is 4–15 KB.

### 8.3 Field notes

- `filename`: `{band_lower}_{class_slug}_{3-digit-number}.jpg` — band `a` or `b`, class slug lowercase with spaces as underscores, number zero-padded (001–200 Band A; 001–100 Band B)
- `split`: `"train"` or `"val"` — pre-assigned from shot_type; Band A val images only; Band B always `"train"`
- `shot_type`: angle code from Section 3.1 (primary classification for this image)
- `prompt_file`: path relative to `data/synthetic/` pointing to the `.txt` file containing the full rendered prompt
- `bokeh`: `true` for the 380 preview images generated with the telephoto/shallow-DoF style; `false` for all remaining images generated with the binocular/sharp-background style. Set at prompt-generation time by `1-generate_image_list.py`; back-filled for existing entries by `1b-migrate_bokeh.py`.
- `status`: pipeline tracking field — `"pending"` → `"generated"` → `"accepted"` / `"rejected_speciesnet"` / `"rejected_no_detection"` / `"regenerated"`

### 8.4 Naming examples

```
images/band_a/walrus/a_walrus_001.jpg         … a_walrus_200.jpg
images/band_a/nine_banded_armadillo/a_nine_banded_armadillo_001.jpg
images/band_b/canada_lynx/b_canada_lynx_001.jpg  … b_canada_lynx_100.jpg

prompts/walrus/001.txt                         … 200.txt
prompts/nine_banded_armadillo/001.txt
prompts/canada_lynx/001.txt                    … 100.txt
```

### 9.2 Image resolution and model

**Model:** `gemini-3.1-flash-image-preview`

**Resolution parameter:** `"512"` — passed as an API-level parameter to the generation call; this controls the output image size without embedding constraints in the prompt text.

**Aspect ratio:** `4:3` (width × height, e.g. 512 × 384 effective pixels).

4:3 is the right choice for this dataset:

- **Matches wildlife photography conventions.** Standard digital cameras and binoculars use 4:3 or 3:2. A 4:3 frame feels like a real field photograph, consistent with the documentary-style prompt.
- **Minimal YOLO padding waste.** Letterboxing a 4:3 image into a 640×640 square adds only ~6% padding rows (vs. ~44% for 16:9). More of the input tensor carries signal.
- **Enough vertical headroom.** Taller animals (wolverine, maned wolf, mouflon standing on rock) fit without cramping; shorter, wider animals (walrus on ice, yak) still have meaningful background context.
- **Not so wide that far-distance shots become empty.** A 16:9 frame at `far` distance puts the animal in a sliver of the frame; 4:3 keeps it comfortably detectable.

**API call parameters** (for `scripts/synthetic/2-generate_images.py`):

```python
response = client.models.generate_images(
    model="gemini-3.1-flash-image-preview",
    prompt=record["prompt"],
    config=types.GenerateImagesConfig(
        number_of_images=1,
        aspect_ratio="4:3",          # closest to 4:3 among supported ratios
        image_size="512",            # resolution parameter
    ),
)
```

> Verify supported `aspect_ratio` and `image_size` enum values against the Gemini API docs at implementation time — the values above are the intended targets; the exact string tokens may differ.

### 9.3 Bounding box annotations

Generated images contain no bounding box labels. Strategy:
1. After generation, run **MegaDetector** on all synthetic images (same pipeline as real images via `filter_results.jsonl`)
2. Images where MegaDetector detects no animal with sufficient confidence are flagged for manual review or regeneration
3. The MegaDetector bbox becomes the training label, just as for real images
4. Expected detection rate: >90% for well-generated images; ~10% failure allowance is within the €170 buffer

### 9.4 Quality control pipeline

1. **Batch trial before full run**: Generate ~50 images for 3 diverse species (one arboreal, one aquatic, one large grazing) before committing to full generation. Manually inspect output quality and prompt-following accuracy.
2. **SpeciesNet filter (automated)**: Run SpeciesNet on all generated images. Flag any image where SpeciesNet top-1 class does not match the intended species (or genus/family). These are candidate re-generations.
3. **MegaDetector filter**: Flag images with no detection at confidence > 0.5.
4. **Regeneration budget**: €170 buffer covers ~3,400 images. A 10% failure rate across 12,600 images = 1,260 re-generations = ~€63. Budget is comfortable.
5. **Tracking**: The JSONL file should be updated with a `status` field (`"generated"`, `"accepted"`, `"rejected_speciesnet"`, `"rejected_no_detection"`, `"regenerated"`) as part of the generation pipeline.

### 9.5 Content safety

Gemini may refuse or degrade output for certain scene types. Avoid:
- Graphic predation (blood, carcasses)
- Explicit mating behavior (use "pair interaction" or "male displaying to female" instead)
- Scenes that look like animal cruelty or trapping

Use instead: alert postures, natural foraging, locomotion, rest, single-animal social displays (vocalizing, scent marking).

### 9.6 Style anchors to include in all prompts

These phrases prevent illustration, cartoon, or overly-HDR outputs:
- "documentary wildlife photography"
- "authentic field conditions"
- "no studio lighting, no artificial backgrounds"
- "photorealistic, natural colors"
- "comparable to BBC Natural World or National Geographic"

## 10. Generation Script Architecture (next deliverable)

### Script 1 — `scripts/synthetic/1-generate_image_list.py`

Produces `data/synthetic/index.jsonl` and all `data/synthetic/prompts/{class}/{nnn}.txt` files. Does not call the Gemini API.

1. Load species config (class name, scientific name, band, guild, Wikipedia files, key diagnostic features)
2. Load Wikipedia `.md` files; extract Description, Behaviour, Habitat sections via section-header parsing
3. For each class, iterate over the shot schedule (160 train + 40 val for Band A; 100 train for Band B)
4. Render the prompt template with species info + shot parameters; photography style selected via `PHOTOGRAPHY_STYLE_BOKEH` / `PHOTOGRAPHY_STYLE_NO_BOKEH` (default: no-bokeh)
5. Write the prompt text to `data/synthetic/prompts/{class_slug}/{nnn:03d}.txt`
6. Append a metadata record to `data/synthetic/index.jsonl` with `"bokeh": false` and `"status": "pending"`

### Script 1b — `scripts/synthetic/1b-migrate_bokeh.py`

One-time migration script (already run). Back-filled the `bokeh` field across all 12,600 `index.jsonl` entries and replaced the photography style sentence in all 12,220 pending `.txt` prompt files. Generated entries (`bokeh: true`) were left untouched. Idempotent on re-run.

### Script 1c — `scripts/synthetic/1c-migrate_closeup.py`

One-time migration script (already run). Converted all 1,488 pending `closeup_head/close` entries to `eye_level/medium` (angle and distance description strings replaced in `.txt` files; `shot_type` and `distance` fields updated in `index.jsonl`). Also appended CRITICAL REQUIREMENT #6 ("fully visible within the frame") to all 11,840 pending prompt files. Generated entries left untouched. Idempotent on re-run.

### Script 2 — `scripts/synthetic/2-generate_images.py`

Reads `index.jsonl`, loads each prompt from its `.txt` file, and calls the Gemini API.

```python
for record in read_jsonl("data/synthetic/index.jsonl"):
    if record["status"] != "pending":
        continue
    prompt = Path("data/synthetic") / record["prompt_file"]
    response = client.models.generate_images(
        model="gemini-3.1-flash-image-preview",
        prompt=prompt.read_text(),
        config=types.GenerateImagesConfig(
            number_of_images=1,
            aspect_ratio="4:3",
            image_size="512",
        ),
    )
    save_image(response, record["filename"], record["band"], record["class"])
    update_status(record, "generated")   # writes back to index.jsonl
```

Status updates are written back to `index.jsonl` after each image so the script is safely resumable after interruption.
