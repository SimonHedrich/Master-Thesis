# Thesis Docs

> Keep this file up to date whenever new files are added to this directory.

Documentation about **producing the thesis document** — the toolchain, the
publishing pipeline, and the decisions behind them. This is the counterpart to
the repo-root `docs/`, which covers the *research*: datasets, models, experiments
and results.

Rule of thumb: if it explains how the manuscript gets written, compiled or
shipped, it belongs here; if it explains what the thesis found, it belongs in
`docs/`.

## Files

| `2026-09-19_overleaf-sync.md` | How `thesis/manuscript/` syncs two-way with Overleaf, and why it is built the way it is. Covers the three mechanisms Overleaf offers (Git integration — chosen — vs. GitHub sync vs. Dropbox), the constraint that shaped the design (Overleaf maps a project to its repo *root*, but the manuscript is a subdirectory of a repo with a 2.6 GB `.git`), and why tree mirroring beat `git subtree` (no force-push, which Overleaf's docs never promise works). Documents the token handling (`OVERLEAF_TOKEN` stays only in the gitignored `.env`, passed to git via an in-memory credential helper), the designated `thesis/overleaf-sync` branch and why the bridge's lack of branch support demands one, the fail-closed guard set, the full 2026-09-19 verification table, an rsync size+mtime bug that silently dropped same-size edits, the `make` interface — `make overleaf` picks a direction from which side moved and refuses when both did, with `overleaf-status|pull|push` to force one — and why it is kept clear of the Makefile's unrelated rsync `sync` block, three bugs the verification caught (rsync's size+mtime comparison silently dropping same-size LaTeX edits; `--allow-any-branch` parsing only before the subcommand, which broke the very invocation the docs recommended; `pull` reporting a one-line incoming edit as a ten-file rewrite), and the two open items — the live `pull` round-trip and the fact that the manuscript has still never been compiled. |
