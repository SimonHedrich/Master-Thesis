\section{Training-Time Data Augmentation}\label{sec:data_augmentation}

Where \Cref{sec:data_sourcing_and_taxonomy,sec:data_quality_and_curation,sec:synthetic_data_supplementation} describe how the dataset itself was constructed, this section describes how it is transformed at training time. An early draft of the augmentation strategy motivated it by a supposed domain shift between iNaturalist-style source imagery and the \textit{AX Visio} binocular's optics. That framing echoed an earlier treatment of augmentation as a tool for closing a sensor-specific gap \cite{hedrichGeneratingSyntheticDatasets2026}. It does not apply here: this thesis includes no AX-Visio-specific evaluation. It therefore needs no simulated-optics transform to design for. Augmentation is instead treated as a variable to be controlled for, in service of the central research question: whether distillation from a teacher outperforms direct fine-tuning. It is not treated as an independent object of study in its own right.

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\subsection{Augmentation as a Controlled Variable}\label{sec:augmentation_controlled_variable}

Two properties of a given augmentation transform determine how it may be used in this experimental design. The first is \emph{distillation compatibility}. Single-image transforms such as flipping, color jitter, and affine scaling preserve a well-defined one-to-one correspondence between an original image and its augmented version. The same augmented image can therefore be shown to both the teacher and the student during distillation. Multi-image compositing transforms such as mosaic, mixup, and copy-paste construct a new image from fragments of several source images. For such a composite, there is no well-defined single teacher view: the teacher would need to independently process and reconcile predictions for several unrelated source crops assembled into one frame. That is not how the teacher is otherwise used. Compositing transforms are therefore never used in the distillation training condition. The second property is \emph{architecture specificity}. Some transforms are architecture-agnostic, such as flipping, color jitter, scale, and translation. Others are coupled to a particular detector family's design: mosaic in particular is tuned to YOLO's anchor-coverage assumptions and is not a generic transform that applies unchanged to arbitrary architectures.

The comparison between Setup A and Setup B isolates the benefit attributable to distillation itself: the two configurations are identical in every respect except the training signal, teacher-guided versus direct. The comparison between Setup A and Setup C is acknowledged as a practitioner's question: \enquote{is distillation with modest augmentation better than direct training with the student's full augmentation budget?} It is not a clean single-factor comparison, since it varies both the training signal and the augmentation policy simultaneously.

The scale and translation transform is deliberately reused from the existing, tested \textit{YOLOv5} \cite{ultralyticsComprehensiveGuideUltralytics} codebase rather than reimplemented. Reuse reduces the risk of subtle bugs in bounding-box coordinate transforms. It also keeps the augmentation pipeline consistent with the student architecture's own reference implementation.

\subsection{Compositing Augmentation (Setup C)}\label{sec:compositing_augmentation}

Setup C adds three compositing transforms on top of the basic set. Mosaic tiles four training images into a single composite frame, at probability $\approx 1.0$, following \textit{YOLOv4}/\textit{YOLOv5} convention \cite{bochkovskiyYOLOv4OptimalSpeed2020}. Mixup linearly blends two images and their labels, at probability $\approx 0.1$, the default used in both \textit{YOLOv5} and \textit{YOLOX} \cite{zhangMixupEmpiricalRisk2018}. Copy-paste pastes segmented instances from one image onto another \cite{ghiasiSimpleCopyPasteStrong2021}. Copy-paste is present in the implementation, but it is a documented no-op in this setting. The ground truth produced by the curation pipeline (\Cref{sec:data_quality_and_curation}) consists of bounding boxes only, with no instance segmentation masks to paste. Its inclusion in the augmentation stack is retained for completeness, and for any future work that adds mask annotations. It contributes no augmentation effect to the experiments reported here. Consistent with common practice, mosaic and mixup are disabled for approximately the final $10\%$ of training epochs (the \enquote{close-mosaic} tail). This allows the model to fine-tune on the true, un-composited image distribution before training ends.

The literature reports meaningful gains from copy-paste-style augmentation in general, on the order of an $8\% \pm 2\%$ mAP improvement. It can reasonably be understood as roughly doubling to tripling the effective variance of a fixed image pool. It is explicitly not treated as a substitute for real training data in this thesis. Augmenting a small set of images many times over produces a model that is well-fit to those images' specific poses and backgrounds, not to the underlying class. This is the reasoning behind the hard $100$-real-image floor implicit in the Band C control condition of \Cref{sec:band_structure}. Augmentation as a variance multiplier is only applied on top of an adequately sized real or synthetic pool, never in place of one.

\subsection{Reproducibility and Confound Control}\label{sec:augmentation_reproducibility}

Because the Setup A/B comparison is the thesis's central result, the two configurations share a single \texttt{CocoYoloDataset}/transforms code path rather than parallel implementations. This way, any difference in outcome can be attributed to the presence or absence of the teacher, not to an implementation discrepancy between two augmentation pipelines. Random-number-generator seeding is controlled so that the same augmented image is shown to the teacher and the student within a given distillation step. An explicit assertion in the distillation training path also verifies that compositing flags are disabled before each run begins, rather than relying on configuration alone. The full augmentation configuration for every run is logged to \textit{MLflow} alongside the standard training metrics (\Cref{sec:model_training_experiment_tracking}). Band A test mAP is logged as a separate diagnostic figure. Band A classes are trained entirely on synthetic imagery, so they are the most likely to reveal augmentation interacting badly with synthetic-image texture artifacts. Scale augmentation, for example, can amplify generation artifacts that would otherwise be imperceptible at native resolution.

The implementation of this augmentation strategy was deliberately sequenced after the ground-truth multi-box annotation fix described in \Cref{sec:gt_annotation_integrity}. Several of the transforms above interact directly with the number and layout of ground-truth boxes on an image. Scale and translation visibility, and mosaic's tiling behavior in particular, behave differently once images can carry genuinely multiple, verified instances. The pre-fix pipeline instead produced a single box per image, and in some cases an incorrectly single one.
