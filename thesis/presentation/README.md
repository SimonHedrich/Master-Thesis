# Final Presentation

Material for the final thesis presentation: a **20-minute talk** to the supervising
professor (research focus: computer vision), the inovex supervisors, and possibly
colleagues working as data/AI engineers.

## Goals

- **Explain the process and the thinking**, not just the results — why each decision
  was made, what went wrong, and what was learned along the way.
- **Detailed but easy to follow.** The audience is technical (CV research, ML
  engineering), but the talk must not depend on having read the manuscript.
- **Tell a story.** Take the relevant parts of the work and thread them together with
  the questions, ideas, and problems that came up, so the talk has a narrative arc
  rather than a chapter-by-chapter summary.

## Slide style

- Slides are **primarily images and graphics** — photos, diagrams, charts.
- **Text is avoided**; where it is needed, it is kept to the bare minimum (a label, a
  number, a few words). The explanation is spoken, not written on the slide.

## Working on the slides (handoff)

Read `slides/README.md` first. This is the short version.

**Current version: `slides/talk_v3.py`** (the 20-minute cut of v2)
- Six scenes, always rendered together in this order:
  `UseCase3 Data3 Generative3 Bands3 Models3 Summary3`. The scene names differ from v2's,
  so both versions' slide files can live side by side in `slides/slides/`.
- 24 slides, 56 click states.
- `Summary3` reuses snapshots that the earlier scenes save with `self.snap()` while
  rendering (`slides/build/cache/snaps_v3/`), which is why all scenes render in one run.
- `talk_v2.py` (shown on 2026-10-19; HTML fallback in `slides/build/talk_v2.html`) and
  `talk.py` (v1) are kept unchanged.
- German speaker script: `final-talk-script-v3.md`, with 55 `[Klick]` markers (one per
  `next_slide()`, none after the last slide). Keep it in sync when the clicks change.
  The slides stay English, the talk is German.
- v3 also needs Ghostscript (`brew install ghostscript`) for `collect_images.py` to render
  the Swarovski Optik EPS logo, and ffmpeg for the BirdID clip on slide 2.

**Project setup**
- `slides/` is a separate uv project, not the repo-root environment. Run everything
  from `slides/`.
- Pins: `manim<0.20` (manim-slides 5.7 breaks on 0.22), `pillow<12`.
- Shared code: `theme.py` (inovex colours, Atkinson Hyperlegible, pills, `photo()`,
  uniform `arrow()`/`curved_arrow()`, `pptx_box()`, the crf-12 encoder override).
  Every number on a slide comes from `data.py`, with its source.
- Images: `images/` (gitignored), rebuilt with
  `uv run python extract_assets.py && uv run python collect_images.py`. NDA pictures
  are under `images/nda/`.

**Commands** (from `slides/`)
- Draft: `uv run manim render -ql talk_v3.py <scenes>`
- Final: `uv run manim render -qk --frame_rate 30 talk_v3.py <scenes>`. Use plain
  `manim render`; `manim-slides render` misparses `-qk`.
- Present: `uv run python present.py -F <scenes>`. It patches a manim-slides bug where a
  4K render overflows smaller screens.
- HTML fallback: `uv run manim-slides convert --offline <scenes> build/talk_v3.html`
- Scroll export: `uv run python export_scroll.py [--static --out build/scroll_static] <scenes>`
- Layout QA: `uv run python qa_frames.py <scenes>` writes the last frame of every slide
  plus contact sheets to `slides/build/qa/`. Look at them after every change.

**Conventions**
- Images and graphics first, minimal text. What is not on the slide is in the script.
- All accuracy numbers on real photos only.
- One highlight colour: green `#7DF381`. Other colours only mark categories: sky blue
  for API generators and real test images, `SOURCE_COLORS` for the image sources,
  yellow `SYNTH_TEST` for synthetic test images (same colour in chart and legend).
- All arrows go through `arrow()`/`curved_arrow()`, so they have the same width everywhere.
- Repo rules (CLAUDE.md): commit straight to `main` and push; stage only your own files;
  never commit rendered media, `images/`, the pptx, or NDA content.
